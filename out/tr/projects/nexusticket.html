NexusTicketGeliştirme ProjesiEtkinlik Biletleme REST API

Bilet Rezervasyonlarında Güvenilirlik Mühendisliği.

Etkinlik yayınlama ve bilet rezervasyonu için bir backend: ödenmemiş rezervasyonlar otomatik olarak iptal edilir, aynı biletin iki kez satılmaması için stok kilitlenir.

Kaynak kodu GitHub'da gör

Kapsam notu:Ödeme akışı API testleri için imzalı bir demo uygulamasıdır; gerçek bir ödeme sağlayıcısına bağlı değildir. Docker Compose yerel geliştirme ortamıdır.

Problem

Bilet satışı bir yarıştır: envanter sınırlıdır, birçok kullanıcı aynı anda rezervasyon yapar ve ödenmemiş rezervasyonlar koltukları sonsuza kadar tutmamalıdır.

Proje Kapsamı

Hesaplar, etkinlikler, bilet sınıfları, yorumlar, çok kalemli rezervasyonlar, kuponlar, rezervasyon süresinin dolması ve demo ödeme akışını kapsayan; OpenAPI dokümantasyonu ve otomatik test paketi içeren bir REST API.

Temel Özellikler

  • JWT ile kayıt, giriş ve yenileme sunan e-posta tabanlı kullanıcı modeli
  • Arama, sıralama ve filtreli etkinlik, sanatçı, kategori ve bilet sınıfları
  • Yalnızca organizatör/personel yazma yetkisi ve kullanıcıya özel siparişler
  • Kapasite doğrulaması ve kuponlu tek veya çok kalemli rezervasyonlar
  • Rezervasyon sırasında bilet sınıfı ve etkinlik satırlarının kilitlenmesi
  • Bekleyen siparişleri iptal edip envanteri geri yükleyen Celery görevi
  • İmzalı ve tek kullanımlık demo ödeme isteği ve onayı
  • Swagger UI ve ReDoc ile OpenAPI şeması; pytest paketi ve GitHub Actions

Teknoloji Yığını

  • Django
  • DRF
  • JWT
  • Celery
  • Redis
  • MySQL
  • Docker
  • pytest
Teknik ayrıntılarMimari, kritik akış ve mühendislik kararları

Mimari

HTTP istemcisi → Django REST Framework → JWT ile e-posta tabanlı kimlik doğrulama → veritabanı. Redis aracılı bir Celery işçisi, ödenmemiş rezervasyonları 15 dakika sonra iptal eder ve envanteri geri verir.

  1. HTTP client

    Swagger UI · ReDoc

  2. Django REST Framework

    accounts · events · orders · payments

  3. Email auth + JWT

    object-level permissions

  4. Database

    SQLite local · MySQL in Docker

Celery worker

expire_order_task · 15 min

Redis

broker · result backend

Kritik Akış

  1. POST /api/orders/
  2. BEGIN transaction
  3. SELECT … FOR UPDATE (ticket classes, events)
  4. validate status · date · capacity · coupon
  5. create order items · increment sold
  6. COMMIT → schedule expiry (15 min)
  7. still pending? cancel + release inventory

Teknik Zorluklar

  • Son biletleri aynı anda rezerve eden iki kullanıcı
  • Terk edilen rezervasyonlardaki koltukları yarış durumu olmadan serbest bırakmak
  • Yalnızca bilet alanların etkinliği değerlendirebilmesini sağlamak

Mühendislik Kararları

  • Rezervasyonda envanter satırlarını kilitlemek için işlem içinde select_for_update
  • İptal veya süre dolumunda envanter ve kupon kullanımının işlemsel olarak geri yüklenmesi
  • View içinde dağınık kontroller yerine nesne düzeyinde yetkiler
  • Gerçek sağlayıcıdan açıkça ayrılmış, imzalı ve tek kullanımlık demo ödemeler

SinShopDevelopment ProjectMultilingual Commerce Platform

Commerce Infrastructure Built for Reliable Transactions.

An online store in four languages — product search, carts, orders and payments — designed so stock and order totals stay correct when many customers buy at once.

View source on GitHub

Scope note:Payment calls require valid ZarinPal merchant configuration, which is not included in the repository. The storefront can be explored with its local demo catalogue.

The Problem

In e-commerce, the hard part is not showing products — it is keeping carts, stock and orders consistent when many people buy at the same time, and handing payment off to a gateway safely.

Project Scope

A full-stack commerce project: a Django REST Framework backend for accounts, catalogue, carts, orders and payments, and a Next.js App Router storefront with locale-prefixed routes and Persian RTL.

Key Features

  • Phone-number user model with JWT login and refresh
  • Catalogue with search, ordering, filters, discounts and stock
  • Guest and authenticated carts with ownership checks
  • Checkout that locks cart, items and products in one transaction
  • Order items that snapshot unit prices at purchase time
  • ZarinPal payment request and callback verification
  • Next.js storefront in four languages, including Persian RTL
  • OpenAPI schema, Swagger UI, throttling, health and readiness probes

Technology Stack

Under the hoodArchitecture, critical flow and engineering decisions

Architecture

Browser → Next.js storefront → same-origin API rewrite → Django REST Framework → database. Celery workers with a Redis broker handle background tasks; payment initiation and verification go through a ZarinPal gateway boundary.

    en · fa · tr · ru

ZarinPal

payment request · callback verify

Critical Flow

  1. POST checkout
  2. BEGIN transaction
  3. SELECT … FOR UPDATE (cart, items, products)
  4. validate active + stock
  5. create Order + unit-price snapshots
  6. decrement stock · clear cart
  7. COMMIT
  8. payment request → gateway callback → verify

Technical Challenges

  • Preventing overselling when two customers check out the same product
  • Keeping order totals correct after prices change
  • Supporting both guest and signed-in carts without leaking ownership

Engineering Decisions

  • Row-level locks during checkout so stock is decremented exactly once
  • DecimalField for every monetary value — no floating-point money
  • Immutable order items with price snapshots
  • Explicit CORS allow-list and separate anonymous / user throttle rates
